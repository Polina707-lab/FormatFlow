## О проекте

**FormatFlow** — подключаемый модуль Eclipse для преобразования файлов между форматами CSV, JSON, XML и YAML. Приложение построено на сервисной архитектуре OSGi: каждый конвертер предоставляется отдельным бандлом и обнаруживается во время выполнения.

Система автоматически находит цепочку преобразований между выбранными форматами. Например, преобразование `CSV → XML` выполняется через промежуточный JSON без необходимости создавать отдельный конвертер для этой пары.

Проект разработан как практический пример использования **OSGi, Eclipse Plug-in Development и SWT/JFace**.

## Возможности

- **Четыре формата:** CSV, JSON, XML, YAML.
- **12 направлений преобразования** между различными форматами — напрямую или через промежуточные конвертеры.
- **Динамическая модульность:** запуск и остановка бандлов без перезапуска Eclipse; доступные направления обновляются при изменении набора сервисов.
- **Автоматический поиск маршрута:** алгоритм поиска в ширину (BFS) выбирает цепочку с минимальным числом преобразований.
- **Фоновое выполнение:** конвертация запускается как Eclipse Job, чтобы не блокировать интерфейс.
- **Предварительный просмотр** исходного и результирующего файлов, а также сообщения о состоянии операции.
- **Обработка больших файлов:** потоковая обработка в конвертерах без необходимости загружать весь документ в память (отдельные вложенные значения могут требовать буферизации).
- **Безопасная запись:** результат формируется через `SafeFileWriter`; промежуточные файлы удаляются после выполнения операции.

## Поддерживаемые преобразования

| Из / В | CSV | JSON | XML | YAML |
|:--|:--:|:--:|:--:|:--:|
| **CSV** | — | Прямое | Через JSON | Через JSON |
| **JSON** | Прямое | — | Прямое | Прямое |
| **XML** | Через JSON | Прямое | — | Через JSON |
| **YAML** | Через JSON | Прямое | Через JSON | — |

> **Обработка вложенных структур.** FormatFlow поддерживает преобразование структурированных данных между различными форматами. При конвертации JSON → CSV вложенные объекты представляются с использованием точечной нотации в названиях столбцов, а массивы сохраняются в виде JSON-строк. При обратном преобразовании CSV → JSON предусмотрено восстановление вложенных объектов и массивов.

## Архитектура

```text
FormatFlow
├── formatflow.api                 # Контракты сервисов и безопасная запись
├── formatflow.core                # Реестр конвертеров и поиск маршрутов
├── formatflow.ui                  # Eclipse ViewPart и интерфейс SWT/JFace
├── formatflow.converter.csvjson   # CSV → JSON
├── formatflow.converter.jsoncsv   # JSON → CSV
├── formatflow.converter.jsonxml   # JSON → XML
├── formatflow.converter.xmljson   # XML → JSON
├── formatflow.converter.jsonyaml  # JSON → YAML
└── formatflow.converter.yamljson  # YAML → JSON
```

**Ключевые компоненты:**

| Компонент | Ответственность |
|:--|:--|
| `FileConverter` | Единый контракт для модулей преобразования |
| `ConverterRegistry` | Обнаружение сервисов через OSGi `ServiceTracker` и уведомление слушателей |
| `ConversionService` | Поиск кратчайшего пути преобразования (BFS) и выполнение цепочки |
| `SafeFileWriter` | Безопасная запись конечного результата |
| `ConverterView` | Основное представление Eclipse, выбор файлов и форматов |
| `FilePreviewPanel` | Предварительный просмотр содержимого файлов |

### Как работает преобразование

```text
Пользователь выбирает исходный и целевой форматы
                         │
                         ▼
              ConversionService
                         │
                         ▼
            ConverterRegistry (OSGi)
                         │
                         ▼
           Поиск маршрута с помощью BFS
                         │
                         ▼
           Выполнение цепочки конвертеров
                         │
                         ▼
            Безопасная запись результата
```

Архитектура FormatFlow основана на едином интерфейсе `FileConverter`, который определяет общий контракт для всех модулей преобразования. Благодаря использованию сервисной модели OSGi новые конвертеры могут динамически подключаться к системе, а механизм автоматического поиска маршрутов обеспечивает их интеграцию с уже существующими преобразованиями.

## Технологии

- **Java 21** — целевое окружение выполнения UI-бандла.
- **OSGi** — жизненный цикл модулей, сервисная модель и динамическое обнаружение сервисов.
- **Eclipse Plug-in Development Environment (PDE)** — разработка и запуск подключаемого модуля.
- **SWT/JFace** — графический интерфейс в Eclipse Workbench.
- **Eclipse Jobs API** — фоновая обработка операций.
- **Gson, StAX, SnakeYAML** — обработка JSON, XML и YAML.

## Запуск в Eclipse

1. Установите JDK, совместимый с настройками проекта (для `formatflow.ui` указан `JavaSE-21`), и Eclipse IDE с **Plug-in Development Environment (PDE)**.
2. Импортируйте проекты-бандлы в рабочее пространство Eclipse через **File → Import → Existing Projects into Workspace**.
3. Убедитесь, что необходимые библиотеки и OSGi-зависимости разрешены, а бандлы конвертеров включены в конфигурацию запуска.
4. Запустите приложение через **Run As → Eclipse Application** (или используйте настроенную конфигурацию запуска Eclipse Application).
5. В запущенном Eclipse Runtime откройте представление **FormatFlow Converter** через **Window → Show View → Other…**, если оно не открылось автоматически.

> Если проект не импортируется или отдельные бандлы не разрешаются, проверьте настройки `MANIFEST.MF`, доступность зависимостей и состав бандлов в **Run Configurations → Plug-ins**.

## Использование

1. Выберите исходный файл (**Source file**).
2. Укажите исходный формат (**From**) и целевой формат (**To**).
3. Выберите путь сохранения (**Output file**).
4. Нажмите **Convert file**.
5. Проверьте сообщение о результате и содержимое файлов в панелях предварительного просмотра.

### Пример: JSON → CSV

Исходный JSON:

```json
[
  {
    "id": 1,
    "name": "Alice",
    "address": { "city": "Minsk" },
    "skills": ["Java", "SQL"]
  }
]
```

Результат CSV:

```csv
id,name,address.city,skills
1,Alice,Minsk,"[""Java"",""SQL""]"
```

Вложенные объекты преобразуются в столбцы с точечной нотацией, а массивы сохраняются в ячейках как JSON-текст.

## Проверка динамической модульности

FormatFlow позволяет включать и отключать конвертеры во время работы Eclipse Runtime.

В OSGi-консоли:

```text
lb
stop <bundle-id>
start <bundle-id>
```

Здесь `<bundle-id>` — идентификатор нужного бандла из вывода `lb`.

При остановке бандла его сервис конвертации перестаёт быть доступен, и интерфейс обновляет список возможных преобразований. После повторного запуска сервис снова обнаруживается без перезапуска приложения.

## Особенности преобразования данных

- **Поддержка вложенных структур.** При преобразовании JSON → CSV вложенные объекты представляются с использованием точечной нотации, а массивы сохраняются в JSON-представлении.
- **Восстановление структуры.** При преобразовании CSV → JSON поддерживается восстановление вложенных объектов и массивов.
- **Обработка значений CSV.** Поскольку CSV не содержит встроенной информации о типах данных, обычные значения при преобразовании в JSON представляются строками.
- **Динамическая доступность форматов.** Набор доступных преобразований автоматически определяется зарегистрированными OSGi-сервисами и обновляется при подключении или отключении модулей.
